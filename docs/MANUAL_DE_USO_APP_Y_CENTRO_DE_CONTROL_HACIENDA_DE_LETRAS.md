# Manual de uso — App y Centro de Control

## Hacienda de Letras

**Dirigido a:** propietarios, responsables de operación y personal autorizado  
**Versión del manual:** 1.1
**Fecha:** 28 de agosto de 2026
**Plataformas:** aplicación móvil Android/iOS y Centro de Control web

---

## 1. Propósito de este manual

Este documento explica, en lenguaje sencillo, cómo utilizar la aplicación móvil de Hacienda de Letras y cómo operarla desde el Centro de Control. Incluye:

- para qué sirve cada módulo;
- qué hace cada botón importante;
- qué información debe capturarse antes de publicar;
- cómo pasa la información del Centro de Control a la app;
- cómo regresan al Centro de Control las reservaciones, compras y solicitudes de los clientes;
- qué revisar cuando un contenido, horario o botón no aparece disponible;
- recorridos completos de operación, desde la publicación hasta el QR o la entrega.

La app de Android y la app de iPhone utilizan los mismos datos y siguen los mismos procesos. Puede haber pequeñas diferencias visuales propias del teléfono, pero la operación descrita en este manual es la misma.

---

## 2. Cómo trabajan juntas la app y el Centro de Control

El sistema tiene dos caras:

1. **La aplicación móvil** es para el cliente. Ahí descubre Hacienda, consulta vinos, experiencias, eventos, cabañas y restaurantes, compra, reserva y revisa sus movimientos.
2. **El Centro de Control** es para los dueños y el personal autorizado. Ahí se publica el contenido, se crean horarios, se atienden reservaciones, se revisan pagos, se preparan pedidos y se validan accesos.

El recorrido general es:

**Centro de Control publica y habilita → la app muestra → el cliente compra, reserva o solicita → el Centro de Control recibe → el personal atiende → la app refleja el resultado.**

### Regla esencial: guardar no es lo mismo que publicar

Un registro puede estar guardado correctamente y todavía no aparecer en la app. Para ser visible normalmente debe cumplir con estas condiciones:

- tener la información obligatoria completa;
- estar en estado **Publicado**;
- estar marcado como **Visible en app** cuando esa opción exista;
- encontrarse dentro de su fecha de publicación;
- tener disponibilidad real cuando se trate de una reservación o venta.

Además:

- una experiencia necesita por lo menos un horario futuro, abierto y reservable;
- un restaurante necesita reservaciones habilitadas y horarios de solicitud;
- una cabaña necesita un paquete publicado y una unidad disponible;
- un evento necesita tipos de boleto publicados, vigentes y con cupo;
- un vino con control de inventario necesita existencia disponible.

### Mapa rápido: qué alimenta a qué

|---|---|---|

## 3. Recomendaciones antes de comenzar

- Ingrese siempre con su usuario personal. No comparta contraseñas.
- Revise que el nombre del sitio sea **admhaciendadeletras.com** antes de capturar datos administrativos.
- No use el botón Atrás del navegador mientras se está mostrando **Guardando**, **Procesando** o **Enviando**.
- Espere el mensaje de confirmación antes de cerrar una ventana.
- Si un botón aparece gris, generalmente falta un dato obligatorio, la operación no corresponde al estado actual o su usuario no tiene permiso.
- Use **Actualizar** después de una operación realizada por otra persona o desde la app.
- Las acciones delicadas, como cancelar, reembolsar, archivar o revocar, muestran una confirmación adicional. Lea el mensaje antes de continuar.

## 9. Reservaciones y boletos

### Crear una reservación de experiencia

1. Seleccione la experiencia.
2. Seleccione un horario real.
3. Ajuste el número de personas.
4. Agregue una nota si existe una necesidad especial.
5. Pulse **Confirmar reservación**.

| Botón o control | Qué hace |
|---|---|
| **Tarjeta de experiencia** | Selecciona la actividad que se quiere reservar. |
| **Tarjeta de horario** | Selecciona fecha y hora. Sólo aparecen horarios abiertos y con cupo. |
| **– / + Personas** | Reduce o aumenta asistentes dentro del cupo permitido. |
| **Notas** | Envía contexto operativo a Hacienda. |
| **Confirmar reservación** | Registra la solicitud y genera su folio. |
| **Actualizar** — flechas circulares | Vuelve a consultar reservaciones y sus estados. |
| **Completar pago** | Abre el checkout cuando la reservación tiene una orden pendiente. |
| **Ver boleto / Mostrar acceso** | Abre el boleto con el QR. |
| **Cancelar** | Solicita la cancelación cuando el estado lo permite. |

### Estados más comunes

- **Pendiente:** Hacienda recibió la solicitud y todavía debe atenderla.
- **Confirmada:** Hacienda aceptó la reservación.
- **Cancelada:** ya no está vigente; el cupo o unidad se libera cuando corresponde.
- **Completada:** el servicio ya fue atendido.
- **No asistió:** el cliente no se presentó.

### Boleto y QR

El boleto muestra folio, fecha, personas o artículos, tipo de acceso y código QR. El QR contiene una dirección segura de Hacienda de Letras y puede abrirse con la cámara normal de iPhone, Android o Google Lens.

Al escanear se abre el boleto público, pero **la lectura por sí sola no consume el acceso**. Desde esa pantalla el cliente puede descargar el boleto en PDF o compartirlo. Para confirmar entrada, llegada, check-in o entrega, el personal inicia sesión con un perfil autorizado y pulsa el botón de confirmación. El sistema registra la operación e impide un segundo uso.

## 18. Checkout y estado de pago

### Antes de pagar

Para compras físicas debe existir un domicilio completo. La app no permite continuar si faltan datos obligatorios.

### Controles principales

| Botón o control | Qué hace |
|---|---|
| **Domicilio guardado** | Selecciona la dirección de entrega. |
| **Usar nueva dirección** | Limpia la selección para capturar otra dirección de entrega. |
| **Agregar/Editar domicilio** | Abre la captura de dirección. Todos los campos marcados son obligatorios para envío. |
| **Guardar esta dirección** | Guarda el domicilio para compras futuras, si el cliente lo activa. |
| **Código de promoción** | Permite escribir un cupón vigente cuando la promoción lo indique. |
| **Crear orden** | Convierte el carrito en una orden con folio y prepara el cobro. Debe pulsarse una sola vez. |
| **Formulario seguro de tarjeta** | Captura los datos del pago cuando el procesador está disponible. |
| **Ver mis órdenes** | Abre Perfil para consultar el folio recién creado. |
| **Volver al checkout** | Regresa después de un pago incompleto. |
| **Reintentar** | Vuelve a consultar el estado; no debe usarse para duplicar una compra ya aprobada. |

### Estados de pago

- **Procesando:** el sistema sigue esperando confirmación.
- **Exitoso:** el pago fue aprobado y la orden continúa.
- **Fallido:** no se confirmó el cobro; puede revisarse o intentarse de nuevo.

Nunca interprete sólo la pantalla del teléfono como conciliación final. La referencia definitiva también debe revisarse en **Centro de Control → Pagos** y **Órdenes**.

## 19. Perfil

### Datos personales

| Botón o control | Qué hace |
|---|---|
| **Español / Inglés** | Cambia el idioma preferido. |
| **Guardar** | Actualiza nombre, nombre visible, teléfono e idioma. |
| **Membresía** | Abre Wine Club o muestra que aún no existe una. |

### Qué datos alimenta Perfil

- **Datos personales:** nombre, correo, teléfono e idioma que identifican al cliente.
- **Preferencias:** aceptación o rechazo de avisos comerciales y operativos.
- **Domicilios:** direcciones usadas para entregas. Una orden puede conservar el domicilio usado al comprar aunque después el cliente edite su perfil.
- **Historial:** reservaciones, accesos, órdenes, pagos y envíos relacionados con esa cuenta.

Si en una orden falta teléfono o nombre completo, primero revise **Clientes** y después el domicilio guardado o capturado en la orden. El domicilio de entrega y el perfil del cliente están ligados, pero se revisan por separado.

### Domicilios de envío

| Botón | Qué hace |
|---|---|
| **Editar** | Carga la dirección en el formulario. |
| **Eliminar** | Quita el domicilio guardado. |
| **Predeterminado** | Define la dirección principal; si ya lo es, el botón aparece deshabilitado. |
| **Usar como predeterminado** | Activa o desactiva esa opción al capturar. |
| **Guardar domicilio** | Guarda sólo cuando todos los campos obligatorios están completos. |
| **Cancelar** | Limpia la edición sin guardar. |

- La campana abre esta sección.
- El número indica avisos sin leer.
- Tocar una notificación la marca como leída y abre la reservación, orden o contenido relacionado cuando existe un destino.

|---|---|

### 36.4 Promociones

Capture nombre, descuento, vigencia, condiciones, límites, segmento y visibilidad. Revise siempre fechas y reglas antes de publicar.

### 36.5 Membresías

Define los planes que se muestran al cliente: nombre, precio, periodicidad, beneficios, límites, vigencia y publicación. La asignación a una persona se hace en **Wine Club**.

### 36.6 Campañas

Prepare nombre, audiencia, contenido, vigencia y estado. Sólo deben utilizarse los canales autorizados y respetarse los consentimientos del cliente antes de enviar o publicar.

# PARTE III — PROCESOS COMPLETOS

## 44. Publicar una experiencia y recibir una reservación

1. Centro de Control → **Experiencias** → **Nueva experiencia**.
2. Complete información, precio, capacidad e imágenes → **Guardar**.
3. Revise **Vista previa** → **Más acciones → Publicar**.
4. Centro de Control → **Disponibilidad → Experiencias y eventos → Nuevo horario**.
5. Capture inicio, fin, capacidad, estado **Abierto** y active **Reservable por clientes** → **Guardar horario**.
6. En la app, abra Experiencias → detalle → Reservar.
7. Seleccione horario y personas → **Confirmar reservación**.
8. La campana del Centro de Control abre la reservación exacta.
9. En Reservaciones pulse **Confirmar**.
10. La app muestra el estado confirmado y el aviso correspondiente.

---

## 45. Habilitar reservaciones de restaurante

1. Centro de Control → **Servicios y sedes → Restaurantes**.
2. Cree o edite el restaurante.
3. Marque **Publicado**, **Visible en app** y **Reservaciones habilitadas** → Guardar.
4. Centro de Control → **Disponibilidad → Restaurantes**.
5. Capture el horario público.
6. Capture las horas reservables, una por línea en formato HH:mm.
7. Seleccione **Habilitadas** → **Guardar horarios**.
8. En la app, seleccione restaurante, fecha, hora y personas → **Solicitar mesa**.
9. La solicitud llega a Reservaciones y a la campana.

---

## 46. Publicar cabañas y recibir una solicitud

1. **Servicios y sedes → Cabañas → Nueva cabaña**: publique el paquete comercial.
2. **Disponibilidad → Cabañas → Agregar cabaña**: cree la unidad física.
3. Compruebe que las fechas estén disponibles y que la unidad no esté Fuera de servicio.
4. En la app, el cliente elige paquete, llegada, salida, huéspedes y notas → **Solicitar cabaña**.
5. El Centro de Control revisa la solicitud en Reservaciones y el calendario.
6. Pulse **Confirmar** o **Validar y reprogramar**, según corresponda.

---

## 47. Vender un boleto y validar el QR

1. **Eventos → Nuevo evento** → complete y publique.
2. Dentro del evento cree por lo menos un tipo de boleto publicado, visible, vigente y con cupo.
3. En la app: Eventos → Detalle → cantidad → **Agregar boleto**.
4. Carrito → **Continuar al pago** → complete el checkout.
5. Cuando el pago se aprueba, el boleto aparece en la app.
6. En la entrada: **Centro de Control → Check-in → Escanear QR**.
7. Revise el resultado → **Registrar check-in**.
8. Un segundo escaneo se rechazará como utilizado.

---

## 48. Vender vino, obtener comprobante QR y completar la entrega

1. **Vinos**: publique la ficha y precio.
2. **Inventario**: registre ubicación, producto y entrada de existencia cuando exista control de stock.
3. App: Vinos → agregar al carrito → Checkout → pago.
4. Cuando el pago se aprueba, la app muestra el comprobante QR de la compra; el cliente puede abrirlo, descargarlo como PDF o compartirlo.
5. **Pagos**: confirme que el cobro tenga el estado esperado.
6. Para entrega presencial, el personal escanea el QR y pulsa **Confirmar entrega**. Un segundo uso queda rechazado.
7. Para envío: **Órdenes → En proceso → Marcar preparando → Capturar guía → Marcar enviado → Marcar entregado**.
8. **Logística** conserva el seguimiento y la app muestra los cambios al cliente.

---

## 49. Atender una solicitud de Celebra

1. El cliente completa Celebra → **Solicitar cotización**.
2. La campana del Centro de Control abre el folio.
3. En **Cotizaciones**, revise contacto, evento, personas, fecha, espacio y notas.
4. Cambie el estado y agregue seguimiento interno.
5. Prepare destinatario, asunto, mensaje, monto y vigencia.
6. Use **Enviar cotización** cuando la propuesta esté autorizada.

---

## 50. Publicar una promoción y usarla en checkout

1. Centro de Control → **Promociones** → **Nueva promoción**.
2. Capture nombre, descripción, tipo de descuento, valor, código, mínimo de compra, vigencia y condiciones.
3. Revise **Vista previa**. Si aplica revisión interna, use **Elegir administrador → Enviar preview**.
4. Cuando esté autorizada, use **Más acciones → Publicar**.
5. En la app, abra **Inicio → Promociones de la semana** o **Menú → Promociones**.
6. Si la promoción tiene código, el cliente lo captura en **Checkout → Código de promoción** antes de **Crear orden**.
7. Revise el resultado en **Órdenes**, **Pagos** y **Reportes**.

Si el descuento no se refleja, revise vigencia, código exacto, mínimo de compra, estado publicado y visibilidad.

4. Usar **Vista previa**.
5. Publicar.
6. Abrir **Vista App** y después revisar en un teléfono.
7. Si es reservable, completar también Disponibilidad.

# PARTE V — SOLUCIÓN DE PROBLEMAS

## 55. “Guardé, pero no aparece en la app”

Revise, en orden:

1. estado **Publicado**;
2. **Visible en app: Sí**;
3. fecha de publicación vigente;
4. imagen y campos obligatorios completos;
5. disponibilidad o inventario, según el módulo;
6. pulse **Actualizar** en el Centro de Control y vuelva a abrir la pantalla de la app.

## 56. “No hay horarios en una experiencia”

Revise **Disponibilidad → Experiencias y eventos**:

- horario futuro;
- estado Abierto;
- Reservable por clientes activado;
- capacidad mayor que cero;
- lugares disponibles;
- sin bloqueo activo.

## 57. “No abre el horario del restaurante”

Revise:

- restaurante Publicado y Visible en app;
- Reservaciones Habilitadas;
- horarios de solicitud capturados, uno por línea;
- formato HH:mm;
- **Guardar horarios** ejecutado.

## 58. “No se puede solicitar una cabaña”

Revise:

- paquete publicado;
- unidad física creada;
- capacidad suficiente;
- fechas sin reservación o bloqueo;
- estado de la unidad distinto de Fuera de servicio.

## 59. “El botón está gris”

Las causas más comunes son:

- falta un campo obligatorio;
- no hay un elemento seleccionado;
- el estado actual no permite esa acción;
- no existe cupo, inventario o disponibilidad;
- se está procesando otra operación;
- el rol del usuario es sólo de consulta o no tiene permiso.

## 60. “El QR abre una búsqueda en Google al escanearlo”

Los boletos nuevos abren una página segura de Hacienda de Letras con el folio, estado y opciones para descargar PDF o compartir. Si un QR antiguo muestra en cambio un texto que comienza con `hdl_pass_`, corresponde al formato anterior: el Centro de Control todavía puede leerlo desde **Check-in → Escanear QR** durante la transición.

## 61. “El cliente no ve un cambio de estado”

1. Confirme que el Centro de Control mostró el mensaje de guardado.
2. Pulse **Actualizar** en el módulo.
3. En la app, pulse Actualizar en Mis reservaciones o vuelva a Perfil/Mis órdenes.
4. Confirme que se está consultando el mismo folio y la misma cuenta.

## 62. “No llegó una notificación”

1. Revise primero la campana interna del Centro de Control o la bandeja del Perfil.
2. Confirme que el aviso corresponde a un hecho operativo, no a una simple visita.
3. Verifique permisos de notificación del teléfono.
4. Abra el registro directamente por folio si la operación sí quedó guardada.

## 64. Regla final de operación

Antes de comunicar al cliente que una acción quedó confirmada, revise el folio y el estado en el módulo correspondiente. El Centro de Control es la referencia operativa para Hacienda; la app es la vista del cliente y refleja la misma información central.

Para evitar errores:

- publique sólo información revisada;
- no invente horarios, cupos, unidades, pagos o entregas;
- no active consentimientos sin autorización;
- no comparta accesos administrativos;
- escanee con cualquier cámara para abrir el boleto y utilice una cuenta operativa para confirmar el acceso;
- registre motivos y notas en las acciones que afectan al cliente.
